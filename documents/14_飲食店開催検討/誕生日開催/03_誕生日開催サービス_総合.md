## 1. 全体結論

| 項目 | 判断 |
| :-- | :-- |
| 誕生日を貸切主催の入口にする案 | **有望。一体型コミュニティ案より有力**。(1) 主催の動機が明確 (2) 日付が決まっている (3) 店は誕生日の顧客データを既に持っている (4) 呼ぶ友達が集客になる |
| ① 自分主催（ネタ化） | **有望・低リスク**。「自分から言い出せない」を笑いに変える。手動で検証できる |
| ② 出会いモード（友達の友達） | **有望。ただし設計と法務の確認が前提**。オプトイン方式で段階導入 |
| ③ 主催者が稼ぐ | **最もリスクが高い。後回し**。最初は非金銭の特典から |
| 最大の課題 | **(a) 日本で成人が自分の誕生日会を主催する文化があるか（未検証）、(b) 1 人あたり年 1 回しか開催できない（供給）** |
| 名称の有力案 | **バースミキサー（大型の混ざる会）／バースリンク（全体ブランド）／バースデーテーブル（少人数の食卓の会）** |
| 次にやること | 開発なしの手動検証（店頭の声かけ・既存会員への案内）。誰が・なぜ主催するのかを実測する |

**特に重要な 3 点**

1. **「年 1 回」は、③「稼ぐ」と最も強く矛盾する。** 誕生日だけだと主催者の実入りは年数千円程度（§9.3）。供給は、店舗主催の月例（05）、合同主催、誕生日以外の記念日で補う。
2. **法務は着手前に弁護士確認が必須**（出会い関連の規制、特商法の連鎖販売取引、景品表示法、個人情報、税務）。特に現金報酬は、確認前に設計を固定しない。
3. **Partiful は「誕生日サービス」ではなくパーティー全般の招待ツール**（§3）。「誕生日に特化したサービスが伸びた」証拠にはならない。招待の拡散を取り入れつつ、店を貸し切る点を独自価値にする。

## 2. 構想と 3 つの方向性

### 2.1 基本構想

店のチラシ等で知った人が「誕生日会をやってみよう」と思い、**主催者が自分の友達を呼んで飲食店を貸し切る**。結婚式二次会のようなノリで、参加者同士の出会いの場にもなる。01 で挙げた「会員主催貸切」の**入口を誕生日に絞る**案。

### 2.2 3 つの方向性

| 方向性 | 内容 |
| :-- | :-- |
| ① 自分主催 | 自分で主催して声がけするのは気恥ずかしいが、「自分主催」を**ネタにする**（「自分で自分を祝っちゃったよ」のノリ） |
| ② 誕生日会を出会いの場に | 結婚式二次会のノリ。友達の友達につながる。主催者は**あらゆるコミュニティの友達を呼べ、全員を知っている顔役（おせっかい幹事）**になる。祝福で皆がご機嫌になり、出会いの確度も上がる。「大型のコンパ・街コン的なノリ」を新しい概念にする |
| ③ 大型合コンで楽しく稼ぐ | 主催者に実入りが入る。人と人をつなぐ楽しさ＋お小遣い稼ぎ |

| 方向性 | 評価 | 要点 |
| :-- | :-- | :-- |
| ① 自分主催 | **有望（低リスク）** | 最大の壁（自分から言い出せない）を笑いに変える。開発負担が小さく、手動で検証できる。日本での受容は未検証 |
| ② 出会い | **有望（設計と法務の裏づけが要る）** | 友人・兄弟姉妹を通じた出会いは約 27%【確認】。街コンより広告費がかからず安全。男女比、主役以外の盛り上がり、法務、供給が課題 |
| ③ 稼ぐ | **後回し** | 供給を増やす決定打になりうるが、連鎖販売取引、「友達を売る」印象、税務、出会い×報酬の見え方が壁 |

| 観点 | ① 自分主催 | ② 出会い | ③ 稼ぐ |
| :-- | :-- | :-- | :-- |
| 解決する課題 | 主催の気恥ずかしさ | 参加の動機・店の大口集客 | 主催者の供給 |
| 魅力（店・主催者） | ◎ | ◎ | ○ |
| 実現しやすさ | ◎ | ○（設計が要る） | △ |
| 法務リスク | 低 | 中〜高 | 高 |
| ブランドリスク | 低 | 中（出会いモードで調整） | 高 |
| 供給（年 1 回）への効果 | ○（循環の入口） | △（解決しない） | ○（ただし矛盾あり） |
| 検証の容易さ | ◎ | ○ | △ |
| **推奨** | **Phase 1 で実施** | **Phase 2 でオプトイン** | **Phase 3 以降、慎重に** |

### 2.3 二層構造（出会いモードの ON/OFF）

| 層 | 名称案 | 位置づけ | 向く人 |
| :-- | :-- | :-- | :-- |
| 入口（全員向け） | **自分主催バースデー**／セルフバースデー | 自分の誕生日を自分で祝う会。出会いは副次的な結果 | 気恥ずかしいが祝ってほしい人、友達に会いたい人 |
| 出会いモード（オプトイン） | **バースミキサー**ほか（§12） | 友達の友達と出会うことを歓迎する誕生日会。主催者が顔役になる | 出会いも楽しみたい人、顔の広い人 |

同じ誕生日会に、主催者が**「出会いモード」を ON/OFF できる**形にする（初期は OFF）。(a) 恋愛目的を好まない友人や店の拒否反応を避け、(b) 出会い志向の人には明確に訴求できる。

### 2.4 一体型コミュニティ案（01）との関係

| 項目 | 一体型（01） | 誕生日会入口の案 |
| :-- | :-- | :-- |
| 入口 | 店のコミュニティ（常連） | 個人の誕生日（友達を呼ぶ） |
| 需要 | 不特定・日常的 | 年 1 回・日付確定 |
| 密度の課題 | 高い（過疎化） | 低い（友達を呼ぶので 1 件で完結） |

**誕生日会は「会員主催貸切」の最小の需要検証単位として有効。** 成功すれば、その参加者が店のコミュニティの種になる（チャット・サブスクは後から足せる）。

## 3. 市場・類似サービス

### 3.1 Partiful は誕生日招待サービスとして伸びたか

**事実（調査で確認できたこと）**

- **伸びている。** 2025 年第 1 四半期の月間ユーザー約 50 万人（前年比 400% 増）、2025 年の新規ユーザーは 200 万人とする報道がある（別の情報源は 2025 年上半期だけで 500 万人としており、数字が食い違う）。利用者の大半は 30 歳未満。
- 資金調達は a16z 主導のシリーズ A1（2022 年 11 月・2,000 万ドル）。直近の評価額は約 1.4 億ドルとする情報がある（出典により差があり未確認）。
- 用途は誕生日にとどまらず、結婚式、a16z が指定したニューヨーク・テックウィークの公式イベント（最大 1,000 人規模）などに広がっている。
- **収益化は遅い。** 無料が基本で、現在の収益は任意のコマース（Instacart のグループ注文: 配送料 5 ドル＋注文額の一部）。2026 年 6 月にアプリ内チケット販売（Stripe 決済）を米国で開始。手数料は非公開だが、競合 Luma の比較ページは「約 10% ＋ 1 件あたり 2 ドル」と記載している（競合側の記述で、未検証）。CEO は「まだ収益化の計画を共有する準備ができていない」と述べている。

**含意（推論を含む）**

1. **Partiful は「誕生日サービス」ではなく、パーティー全般の招待ツール。** 誕生日が主要用途の 1 つであることは確からしいが、比率を示す数字は確認できなかった。
2. **成長の核は招待の拡散と参加の手軽さ**（一般知識: ゲストはアプリ不要で、電話番号で出欠を返せる。招待を受けた人が次の主催者になる）。会場やレストランとの連携で伸びたわけではない。
3. **収益化に 8 年近くかかっている**（創業は 2017 年とされる。一般知識）。招待ツールとしての成長と、事業としての収益は別の問題。
4. **主催者は少なく参加者は多い**。ゲストが次の主催者になる循環がユーザー獲得コストを下げている。

**shokujii への示唆**

| Partiful の強み | shokujii での応用 | 注意 |
| :-- | :-- | :-- |
| 招待が楽しく、友人に送りやすい | 招待ページを魅力的にし、ゲストは **LINE ですぐ出欠・事前注文** | 日本は LINE が前提。電話番号認証より LINE ログインが自然 |
| ゲストがアプリ不要 | ゲストの登録を最小化 | 事前決済・アレルギー情報の入力は避けられない。入力を軽くする |
| 無料で広がる | **主催者は無料**にし、店への送客・飲食売上から対価を得る | 収益化を後回しにできる資金力が要る |
| 場所を選ばない | shokujii は **店を貸し切る前提**。場所探しと予約を同時に解決 | Partiful にない独自価値で、同時に弱みでもある（店の協力が必須） |

| :-- | :-- | :-- |
| G1 | **主催の動機が明確で、日付が決まっている** | 誕生日は毎年必ず来る。他の貸切（歓送迎会など）より個人的で強い |

## 5. うまくいかない理由と対策

優先度は「発生可能性 × 致命度」の主観評価。**U1〜U4 は事業の成否を左右する。**

### U1. 日本では大人が「友達を集めて誕生日会を自分で主催する」習慣が弱い可能性【高／高】

- **理由**: Partiful の成功は米国の Gen Z の文化に支えられている（推論）。日本の成人の誕生日は、恋人・家族・親しい少人数で祝うのが中心で、自分で主催して大人数を呼ぶのは気恥ずかしい人が多い可能性（推論。要検証）。
- **失敗の形**: 主催者が現れず、機能だけ作って稼働しない。
- **対策**:
  1. **主催者を「本人」に限定しない**。友人が主催するサプライズ、推し誕（本人不在）、子どもの誕生日会（ママ会）、周年・還暦などの節目まで広げる。「幹事が主催して本人を祝う」形が日本では自然（推論）。
  2. **「祝う会」「お祝いパーティー」**として訴求する。
  3. **ネタ化する**（§6 方向性①）。気恥ずかしさを笑いに変える。
  4. 最初は日本で需要が実証されている層（推し活、20 代の少人数グループ）から始める。
  5. 検証（§13）で「誰が、誰のために」主催するのかを最初に確認する。

### U2. 店頭チラシからの転換率が低い【高／高】

- **理由**: 来店者 × 誕生日が近い × 友達を呼べる × 貸切したい、の掛け算で対象者が極めて少なくなる（推論）。
- **対策**:
  1. **店の既存会員の誕生日データから能動的に案内**（G2）。誕生日の約 1 か月前に LINE で配信。
  2. 店頭の接点を複数持つ（チラシ、テーブルの QR、会計時の声かけ、サプライズを実施した客への「次はあなたが主催」）。
  3. ゲストが次の主催者になる循環（招待ページの「あなたも開く」）。
  4. 導入初期は、スタッフが積極的に提案する運用で需要の初期値を確認する。

### U3. 主催者の負担・リスクが大きい【中〜高／高】

- **理由**: 人数が集まらない場合の最低消費額、出欠管理、集金、アレルギー確認、当日進行。本人が主催する場合、自分の会の費用を自分で負担するのか曖昧で気まずい。
- **対策**: (1) 最低人数未達なら自動で不成立にして全額返金、(2) **主役無料の割り勘**を標準に、(3) 参加者が自分で事前決済・メニュー選択（既存機能）、(4) 店側のケーキ・デザートプレート・飾り付けのオプションで「お店にお任せ」。

### U4. 収益性が低い【高／高】

- **理由**: 主催者無料のサービスは、収益源が店の売上からの手数料に限られる。誕生日会は客単価が居酒屋の宴会レベルで、手数料率が数%では 1 件あたりの粗利が小さい。決済手数料（Stripe は一般に約 3.6% 前後。要確認）を引くと薄い。店への月額課金は、LINE レストランプラス（1 年目は実質 0 円）の存在で取りにくい。
- **対策**: (1) 収益を複数持つ（貸切成立手数料 5〜10%、ケーキ・花・装飾のアドオン、優先掲載）、(2) 客単価を上げる設計（コース・ドリンク・貸切料・プレート）、(3) 1 店舗あたり月に何件の貸切が成立すれば粗利が出るかを先に確定、(4) 歓送迎会・女子会・同窓会に広げられる設計（04）。

### U5. 店側の協力が得られない・運営負荷【中／高】

- **理由**: 貸切は仕込み・人員の確保が必要で、繁忙時は通常客の機会損失。飾り付け・サプライズ・ケーキ持ち込みの個別対応が増える。
- **対策**: 貸切可能な曜日・時間・最低消費額・人数・受付期限・持ち込み可否を店が細かく設定でき、承認制にする。参加者の注文確定リストとアレルギー情報を事前に渡す。サプライズ・装飾は店が定めたオプションの範囲に限定。初期はすでに貸切・サプライズ対応を実施している店から。

### U6. 既存の代替手段で足りる【高／中〜高】

- **理由**: 主催者は LINE グループで集め、ぐるなび・ホットペッパーで予約し、割り勘は PayPay 等。現状でも困っていない可能性。日本では LINE が出欠・連絡の面倒を解決している。
- **対策**: 「予約・事前決済・出欠・割り勘・アレルギー確認が **1 つのリンクで終わる**」体験を核に。LINE と競合せず、**LINE グループへ招待リンクを貼るだけ**で使える設計。解決する課題の優先順位（日程調整、集金、店探し、サプライズ手配のどれが最も面倒か）を検証で確認。

### U7. 「出会いの場」を前面に出すことの法務・安全・ブランドリスク【中／高】

- **理由**（一般論。専門家確認が必須）: 異性との出会いを目的とした仲介にあたる場合の出会い系サイト規制法や関連法令、友達の友達が参加する形でもナンパ・ハラスメント・勧誘（マルチ商法・宗教・投資）が持ち込まれる恐れ、酒類提供に伴う未成年・泥酔・事故。
- **方針**: 出会いは**オプトインの「出会いモード」**として段階導入する（§8）。初期は OFF。法務確認後に追加。
- **対策**: 参加を主催者の招待に限る（クローズド、友達の友達まで）。本人確認、通報・ブロック・店による参加拒否権、営利・勧誘の禁止規約。詳細は §8.4。

### U8. 需要が季節・日付に偏り、稼働が安定しない【中／中】

- **理由**: 金・土の夜に集中しやすく、店が貸切を出したくない繁忙時間に需要が偏る一方、平日の閑散帯には需要がない（推論）。
- **対策**: 平日・ランチ・休日昼の貸切割引、時間帯別の最低消費額、ランチ・アフタヌーンティー形式の提案。

### U9. 競合・代替の追随【中／中】

- **理由**: ぐるなび・ホットペッパー、Rounge、スペースマーケットが「招待・出欠」を足せば代替できる。Partiful や Luma の日本参入の可能性。
- **対策**: 機能ではなく**店舗ネットワーク（誕生日貸切に協力的な店の密度）**と、**既存会員データ・誕生日の導線**で優位を作る。特定の地域・業態に集中して先行。

## 9. 「年 1 回」問題と供給設計

### 9.1 構造

- 1 店舗が**月 4 回**開くには年 48 人の主催者が要る。**毎日**なら年 365 人。
- 誕生日だけを入口にすると、供給は主催者の母数に完全に依存する。

### 9.2 解決策

| # | 方法 | 内容 | 効果 | 確度 |
| :-- | :-- | :-- | :-- | :-- |
| 1 | **参加者が次の主催者になる循環** | 参加者の誕生日は 1 年以内に必ず来る。招待ページに「あなたも自分主催してみる？」 | 下のモデル | 高 |
| 2 | **誕生日以外の「自分主催」理由を増やす** | ハーフバースデー、プレ誕・後夜祭、誕生月まるごと、記念日（入社・転職・引っ越し・昇進・資格取得・ダイエット達成・禁煙）、ゾロ目の年齢、年男・年女 | 1 人あたりの主催回数が増える | 高 |
| 3 | **合同主催**（同じ月生まれ 2〜3 人で 1 つの会） | 負担を分担。呼べる友人の母集団が増え、**混ざる範囲が広がり出会いの確度も上がる** | 負担減・規模拡大 | 高 |
| 4 | **友人主催（祝う側が幹事）** | 友達の数だけ主催できる | 年 1 回に縛られない | 中 |
| 5 | **店舗主催の月例**（BIRTHDAY PARTY ほか。[05](../飲食店主催/05_店舗主催定例イベント検討.md)） | 個人主催に頼らず、店が毎月開催。個人の誕生日会への入口にもなる | **供給の安定** | 中 |
| 6 | **「同じ誕生日・同じ月・同じ星座」の出会い軸** | 見知らぬ者同士でも共通点が会話の種になる | 新しい軸、供給 | 低（需要未検証） |
| 7 | **顔役（常連の幹事）プログラム** | 顔の広い人に継続的に主催してもらう。**③と接続するが法務リスクが高い（§10）** | 主催回数を大きく増やせる | 低 |

**循環のモデル（仮置き）**: 1 回の参加者を N 人、そのうち次に自分で主催する割合を c とすると、次世代の主催数は **N × c**。**N × c が 1 を超えれば自己持続**（例: N＝25 なら c が 4% 以上、つまり 25 人中 1 人が次に主催すれば維持）。誕生日は 1 年以内に来るが、**平均で約半年のタイムラグ**がある。立ち上げ初期は店舗主催や手動の種まきで補う。

### 9.3 ③「稼ぐ」との矛盾

- 主催者への還元を**参加者 1 人あたり 100〜300 円**（仮置き）とすると、30 人規模の会で 3,000〜9,000 円。**年 1 回だけなら年 3,000〜9,000 円で、お小遣いにもならない**。
- 月 1 回主催（9,000 円/回）なら年約 11 万円で副業に近い水準。ただし**継続的な出会い仲介で報酬を得る形**になり、法務リスクが一段上がる（§10）。
- 結論: 「稼ぐ」を成立させるには主催回数を増やす必要があるが、その分リスクも増える。**先に供給（§9.2 の 1〜5）を作り、報酬は後から検討する。**

## 10. 方向性③ 主催者が稼ぐ仕組み

### 10.1 報酬の 3 段階

| 段階 | 内容 | 例 | リスク |
| :-- | :-- | :-- | :-- |
| L0 特典（非金銭） | 主役無料、ケーキ、ドリンク、次回の割引、主催者ランク | 「20 人以上で主役のコースが無料」 | 低 |
| L1 ポイント還元 | 店・プラットフォームのポイント | 参加者 1 人につき 100pt | 中（前払式支払手段にあたるかの確認：有効期限・発行条件） |
| L2 現金報酬 | 参加者数・売上に連動 | 売上の 2〜3%、1 人あたり 100〜300 円 | **高** |

### 10.2 L2（現金報酬）のリスク

| # | リスク | 内容 | 対策 |
| :-- | :-- | :-- | :-- |
| 1 | **連鎖販売取引（特商法）** | 報酬を得る人が他の人を勧誘して組織を広げ、その取引に応じて報酬を得る構造（かつ金銭負担を伴う）は連鎖販売取引として規制される【一般論】。**主催者が別の主催者を勧誘し、その分も報酬になる設計は避ける** | **単段のみ**（主催者は参加者を連れてくる報酬のみ）。主催者になるのに金銭負担をさせない。弁護士確認 |
| 2 | **「友達を売る」印象** | 報酬目当てと思われ関係が悪化 | 報酬の存在を**参加者に開示**。報酬を受け取らず特典にする選択肢 |
| 3 | **異性紹介・接待に近い見え方** | 男女で報酬や料金が違う、「女性を連れてくれば稼げる」と読める設計は、キャバクラ的・風俗的な連想（風営法の該当性は運営形態に依存し要確認） | **性別・容姿で報酬に差をつけない**。「稼げる」「可愛い子を呼べば」の訴求をしない |
| 4 | **税務** | 雑所得等になりうる。給与所得者は副業所得が年 20 万円超で申告が必要。事業者側の支払調書・源泉徴収の要否【一般論】 | 税理士に確認。年間上限、本人確認 |
| 5 | **景品表示法・誇大広告** | 「稼げる」が副業詐欺と誤認される | 金額の例示は実績ベース、上限・条件を明記 |
| 6 | **不正（水増し・サクラ）** | 実在しない参加者で報酬を得る | 来店・飲食代の**支払い確定後に付与**。本人確認、同一端末の検知 |
| 7 | **店・プラットフォームの信頼** | 「出会い×お金」で詐欺・マルチ・風俗の連想 | 運営の透明性、運営会社名の表示、規約 |
| 8 | **主催者の責任の増大** | 報酬を受け取ると、事故時に「業として」の責任を問われうる | 責任分界の明確化、保険、規約 |

### 10.3 推奨

1. **最初は L0（非金銭の特典）のみ**。「楽しい」「顔役になれる」を動機にし、主役無料・ケーキ・次回割引で報いる。
2. L2 は**弁護士・税理士の確認後**、小規模実験として単段・性別非依存・支払確定後付与で検討。
3. 訴求は「稼げる」ではなく「**お店からのお礼**」「**顔役への感謝**」。
4. 「顔役プログラム」（継続的な主催＋報酬）は、継続的な出会い仲介の事業性を帯びるため、最も慎重に扱う（Phase 3 以降）。

### 10.4 店にとっての見え方

主催者への還元は、店から見れば**成果報酬型の集客費**。店が広告に払う 1 人あたりの獲得コストより小さければ成立する（推論。店の現在の集客費の確認が要る）。店が負担するか、プラットフォームの手数料から出すかを整理する必要がある（07 §8 #1）。

### 12.5 採用前の確認

1. **商標**（J-PlatPat）、ドメイン、SNS アカウント名の空き状況。「主役ナイト」「友の友会」など一般的な語は先行使用の可能性が高い。
2. **検索性**: 名前で検索したとき、他のサービスや一般語に埋もれないか。
3. **店・広告媒体の審査**: 出会いを連想する語が Instagram 広告や店の掲示で問題にならないか（特に「コン」系）。
4. **読み方**: 「自祝」「自画自祝」のように読みにくい語は、ふりがなを併記。
5. **既存サービスとの衝突**: 「Toast」（POS）、「Circle」（コミュニティ SaaS）、「Mixer」（調理器具の意味）、「Table」系の予約サービスなど。
6. **A/B テスト**: 2〜3 案を招待ページ・店への DM の反応（クリック、返信）で選ぶ（07 §9 のテスト設計に組み込む）。

## 15. 確認事項・注意事項

### 15.1 営業・開発前に確認すること

1. **名称の商標調査**と、広告・SNS での使用可否。
2. **弁護士**: 出会い関連の規制、特商法（連鎖販売取引、通信販売の表記）、景品表示法、個人情報（交際希望・連絡先・アレルギー）、風営法上の見え方、資金決済法（ポイント）、決済スキーム（店舗直接入金）。
3. **税理士**: 主催者への報酬の取り扱い（雑所得、源泉徴収、支払調書）。
4. 店の受け入れ（出会いモードを許可する店の割合）と、ナンパ・トラブル時の対応ルール。
5. 2 つのモード（出会いあり／なし）の表示と、参加者の同意取得の設計。
6. 既存の**最小催行人数・自動中止**・返金・アルバムの実装状況【仕様書】。
7. 店舗側の手数料条件（07 §8 #1）。
8. U1 の検証結果（日本で誰が自分で主催するか）。

### 15.2 注意事項

- Partiful の収益・評価額・ユーザー数は報道や比較サイトによる推定で、情報源ごとに数字が異なる。誕生日用途の比率は確認できなかった。Luma の比較ページにある Partiful の手数料は競合側の記述で、公式の数字ではない。
- 日本の誕生日会の習慣、LINE の代替性、チラシの転換率は**推論**で、検証が必要。サプライズの嬉しさを示す調査は対象が高校生で、成人には直接当てはまらない。
- 「自分主催」のネタ化が日本で受け入れられるかは**未検証**。「祝福ムードが出会いの確度を上げる」は**仮説**。
- 出会いの経路の統計（友人・兄弟姉妹を通じて約 27%）は、2015〜2018 年の結婚を対象とした**夫婦が出会ったきっかけ**であり、誕生日会での出会いの確度を直接示すものではない。検索結果の要約をもとにしており、原典で確認する。
- 推し活市場の規模（約 3.9 兆円）、推し誕の平均支出（約 1 万円）は調査会社・記事の数字で、調査方法・対象は未確認。
- 名称は、類似の既存使用を**今回の検索範囲では確認できなかった**だけで、不存在の保証ではない。
- ③の現金報酬は、現時点では**設計を固定しない**。法務・税務の確認を先行する。
- 幹事代行・二次会サービスは今回未調査（追加調査の候補）。
- 試算（還元額、循環モデル）と評価（◎○△、順位、確度）は仮置きで、実績で更新する。
- 法務の記述は一般論で、専門家の確認を代替しない。
