# 誕生日会開催サービスの検討（Partiful の考察・類似サービス・成否と対策）

構想: 店のチラシ等で知った人が「誕生日会をやってみよう」と思い、**主催者が自分の友達を呼んで飲食店を貸し切る**。結婚式二次会のようなノリで、参加者同士の出会いの場にもなる。前回の「一体型コミュニティ」の評価（01_事業性評価_成功可能性と失敗リスク.md）で挙げた「会員主催貸切」の**入口を誕生日に絞る**案。

- 作成日: 2026-10-07
- 根拠: 本書の Web 調査（2026-10）、既存の 00_サービス機能一覧_統合サマリ.md
- **推論を含む。数値は仮置き。** 出典の無い記述は一般知識または推論で、その旨を明記した

## 1. 結論

| 項目 | 判断 |
| :-- | :-- |
| 「誕生日」を貸切主催の入口にする案 | **有望。一体型よりも有力**。理由: (1) 主催の動機が明確 (2) 日付が決まっている (3) 店は誕生日の顧客データを既に集めている (4) 呼ぶ友達が集客になる |
| 最大の課題 | **「大人が友達を集めて誕生日会を自分で主催する」文化が日本で十分にあるか**は未検証。チラシ経由の転換率も未知 |
| 「出会いの場」を前面に出す | **リスクが高い**（法規制・安全・店のブランド）。初期は付加価値として扱い、主目的にしない |
| 次にやること | 手動運用による需要検証（§8）。本開発は検証後 |

## 2. Partiful は誕生日招待サービスとして伸びたか

### 2.1 事実（調査で確認できたこと）

- **伸びている。** 2025 年第 1 四半期の月間ユーザー約 50 万人（前年比 400% 増）、2025 年の新規ユーザーは 200 万人とする報道がある（別の情報源は 2025 年上半期だけで 500 万人としており数字が食い違う）。利用者の大半は 30 歳未満。
- 資金調達は a16z 主導のシリーズ A1（2022 年 11 月・2,000 万ドル）。直近の評価額は約 1.4 億ドルとする情報がある（出典により差があり未確認）。
- 用途は誕生日にとどまらず、結婚式、a16z が指定したニューヨーク・テックウィークの公式イベント（最大 1,000 人規模）などに広がっている。
- **収益化は遅い。** 無料が基本で、現在の収益は任意のコマース（Instacart のグループ注文: 配送料 5 ドル＋注文額の一部）。2026 年 6 月にアプリ内チケット販売（Stripe 決済）を米国で開始。手数料は非公開だが、競合 Luma の比較ページは「約 10% ＋ 1 件あたり 2 ドル」と記載している（競合側の記述で、未検証）。CEO は「まだ収益化の計画を共有する準備ができていない」と述べている。

### 2.2 重要な含意（推論を含む）

1. **Partiful は「誕生日サービス」ではなく、パーティー全般の招待ツール。** 誕生日が主要な用途の 1 つであることは確からしいが、誕生日の比率を示す数字は今回の調査で確認できなかった。「誕生日会に特化したサービスが伸びた」証拠にはならない。
2. **成長の核は招待の拡散と参加の手軽さ**（一般知識: ゲストはアプリ不要で、電話番号で出欠を返せる。招待を受けた人がそのまま次の主催者になる）。会場やレストランとの連携で伸びたわけではない。調査でも提携の言及はなかった。
3. **収益化に 8 年近くかかっている**（Partiful の創業は 2017 年とされる。一般知識）。「招待ツールとしての成長」と「事業としての収益」は別の問題。
4. **主催者の数は少なく、参加者は多い**。招待されたゲストが次の主催者になる循環が、ユーザー獲得コストを下げている。shokujii も同じ構造を取れるかが鍵。

### 2.3 shokujii への示唆

| Partiful の強み | shokujii での応用 | 注意 |
| :-- | :-- | :-- |
| 招待が楽しく、友人に送りやすい | 誕生日会の招待ページを魅力的にし、ゲストは **LINE ですぐ出欠・事前注文** できるようにする | 日本は LINE が前提。電話番号認証より LINE ログインが自然 |
| ゲストがアプリ不要 | ゲストの登録を最小化（会員登録なし） | 事前決済・アレルギー情報の入力は避けられない。入力を軽くする設計が要る |
| 無料で広がる | **主催者は無料**にし、店への送客・飲食売上から対価を得る | Partiful のように手数料の収益化を後回しにできる資金力が必要 |
| 場所を選ばない | shokujii は **店を貸し切る前提**。場所探しと予約を同時に解決する | ここが Partiful にない独自価値で、同時に弱みでもある（店の協力が必須） |

## 3. 類似サービス・事例

「誕生日会」「貸切」「招待」「幹事支援」の 4 つの要素に分けて整理する。**4 つを一体で提供するサービスは確認できなかった。**

| 分類 | サービス | 内容 | 誕生日会との関係 | 備考 |
| :-- | :-- | :-- | :-- | :-- |
| 招待・出欠 | **Partiful**（米） | パーティー招待、出欠、アプリ内チケット | 誕生日が主要用途と見られる | 場所は提供しない |
| 招待・出欠 | Evite / Paperless Post / Punchbowl（米） | デジタル招待状。有料プランは小規模 18 ドル〜、Paperless Post は 1 人あたり約 0.13〜0.48 ドルのコイン制 | 誕生日・結婚式など | 収益の中心は招待状の販売。Paperless Post は 2020 年の売上が 85% 減少し、その後回復したと報じられた |
| 招待・出欠 | Luma / Peatix（国内含む） | イベントページ、出欠、チケット販売。Luma は有料チケットのプラットフォーム手数料 0%（有料プラン）〜5% | 交流会・セミナー向けが中心 | 日本語対応あり |
| 場所（貸切） | **スペースマーケット / インスタベース**（国内） | レンタルスペースの時間貸し。「誕生日会」「推し誕」用途の特集あり。飾り付け済みのスペース、ケータリング注文が可能 | **本人不在の誕生日会（推し誕）が定番化していると紹介されている** | 飲食店ではなくスペース。飲食は持ち込み・ケータリング |
| 場所（貸切） | **Rounge**（国内） | 貸切可能なダイニングバー・居酒屋など約 21,000 店を検索 | 誕生日サプライズ対応の店あり | 検索・見積もり中心。主催者を支援する機能は限定的と見られる（未確認） |
| 場所（貸切） | ぐるなび / ホットペッパー | 店ごとに誕生日サプライズ・貸切・二次会プランを掲載 | 店の個別プラン | 友達への招待・出欠の仕組みは別（LINE 等） |
| 場所（米） | Peerspace / Splacer / Tripleseat | 会場の時間貸し、ホスピタリティ向けのイベント管理 | パーティー全般 | 招待・出欠機能は薄い |
| 幹事支援 | 幹事代行・二次会代行 | 結婚式二次会、歓送迎会の幹事を代行 | 二次会に近い | 詳細は今回未調査（要追加調査） |
| 出会い・食事会 | Timeleft / Gourmate / LYMiN / DMA など | 見知らぬ人を集めた食事会 | 誕生日ではない | 主催はプラットフォーム。主催者が友達を呼ぶ形ではない |
| 店の誕生日施策 | 各社 CRM の誕生日クーポン（GATE など） | 店が顧客の誕生日に配信 | 来店の動機づけ | **店は誕生日データを既に持っている** |

**所見**:
- 「友達を呼ぶ招待」と「店の貸切予約」は別々のサービスに分断されている。主催者は LINE で友達を集め、電話やグルメサイトで店を探し、割り勘は手作業で行っている（推論）。
- 国内で近いのは「スペースマーケット × 推し誕」（場所）と「ぐるなび・ホットペッパーの誕生日プラン」（店）。招待・出欠・事前決済・割り勘を貸切と結びつけたサービスは確認できなかった（調査範囲の制約あり）。

## 4. うまくいく理由

| # | 理由 | 根拠・補足 |
| :-- | :-- | :-- |
| G1 | **主催の動機が明確で、日付が決まっている** | 誕生日は毎年必ず来る。イベントを自発的に企画する動機が、他の貸切（歓送迎会など）より個人的で強い |
| G2 | **店が顧客の誕生日を既に持っている** | 既存の CRM は誕生日クーポンを配信している。**店の会員に「誕生日の 1 か月前に貸切のご案内」を送る**導線を作れる（チラシ以外の入口になる） |
| G3 | **呼ばれた友達が次の見込み客・主催者になる** | Partiful と同じ招待による循環。ゲストの自己負担で店の新規客が生まれる。店の集客コストは 0 |
| G4 | **店にとって貸切は売上の見込みが立つ** | 最低消費額・人数・日時が事前に確定する。閑散時間帯・平日の稼働に使える |
| G5 | **推し活（推し誕）という既存の旺盛な需要** | 本人不在の誕生日会が定番化していると紹介され、レンタルスペース事業者が特集している。「友達を呼ぶ」以外にも、同じ推しのファンが集まる形がある |
| G6 | **事前決済・メニュー選択の既存機能が使える** | shokujii の既存の強みが「誕生日会の割り勘・コース選択」にそのまま使える |
| G7 | **インクルーシブ対応** | 友達が多様な食の制約を持っていても、招待ページで事前に確認できる（shokujii の独自価値） |
| G8 | **出会いの付加価値** | 友達の友達と出会える。二次会のような場の需要はあるが、主目的にしないほうが安全（§5 U7） |

## 5. うまくいかない理由と対策

優先度は「発生可能性 × 致命度」の主観評価。**U1〜U4 は事業の成否を左右する。**

### U1. 日本では大人が「友達を集めて誕生日会を自分で主催する」習慣が弱い可能性【可能性: 高 / 致命度: 高】

- **理由**: Partiful の成功は米国の Gen Z の文化（ホームパーティー、誕生日にパーティーを開く習慣）に支えられている（推論）。日本の成人の誕生日は、恋人・家族・親しい少人数で祝うのが中心で、**自分で主催して大人数を呼ぶのは気恥ずかしい**と感じる人が多い可能性がある（推論。要検証）。「自分の誕生日に友達を呼びつける」ことへの心理的抵抗もある。
- **失敗の形**: 主催者が現れず、機能だけ作って稼働しない。
- **対策**:
  1. **主催者を「本人」に限定しない**。**友人が主催するサプライズ誕生日会**、**推し誕（本人不在）**、**子どもの誕生日会（ママ会）**、**周年・還暦などの節目**まで対象を広げる。「幹事が主催して、本人を祝う」形が日本では自然（推論）。
  2. **「誕生日会」という名称にこだわらず、「祝う会」「お祝いパーティー」**として訴求する。
  3. 最初は **日本で需要が実証されている層**（推し活、20 代の少人数グループ）から始める。
  4. 検証（§8）で「誰が、誰のために」主催するのかを最初に確認する。

### U2. 店頭チラシからの転換率が低い【可能性: 高 / 致命度: 高】

- **理由**: チラシで知った客が、**その場で貸切の誕生日会を企画するところまで進む転換**は、段階が多く低くなる。（来店者 × 誕生日が近い × 友達を呼べる × 貸切したい）の掛け算で、対象者が極めて少なくなる（推論）。チラシの 1 回の来店者が 1 日の客数のごく一部に限られる。
- **失敗の形**: 導入店舗の主催数が月 1 件未満で、店が使わなくなる。
- **対策**:
  1. **店の既存会員の誕生日データから能動的に案内する**（G2）。誕生日の約 1 か月前に、LINE などで「お友達と貸切で祝いませんか」を配信する。対象者が明確で、タイミングも最適。
  2. **店頭の接点を複数持つ**: チラシ、テーブルの QR、会計時、誕生日サプライズを実施した客への「次はあなたが主催」。
  3. **主催した客の友達（ゲスト）が次の主催者になる循環**を設計する（招待ページに「あなたも誕生日会を開く」を置く）。
  4. 導入初期は **店の貸切を店側が積極的に提案**する運用（スタッフが声をかける）を前提にし、需要の初期値を確認する。

### U3. 主催者の負担・リスクが大きい【可能性: 中〜高 / 致命度: 高】

- **理由**: 人数が集まらない場合の最低消費額、友達の出欠管理、集金（割り勘）、アレルギー確認、当日の進行。誕生日の本人が主催する場合は、**自分の誕生日会の費用を自分で負担するのか**が曖昧で、気まずさがある。
- **対策**:
  1. **主催者の負担をゼロにする**: 最低人数に達しなければ自動で不成立にして、全額返金する。
  2. **費用負担を選べる**: 割り勘、**本人は無料（ゲストが割り勘で主役の分を負担）**、主催者が全額など。主役無料の割り勘を標準にして、「自分が払う気まずさ」を避ける。
  3. 招待ページで **参加者が自分で事前決済・メニュー選択**する（shokujii の既存機能）ことで、主催者の集金・取りまとめを不要にする。
  4. 店側に **ケーキ・デザートプレート・飾り付けのオプション**を設定させ、主催者が「お店にお任せ」できるテンプレートを提供する。

### U4. 収益性が低い【可能性: 高 / 致命度: 高】

- **理由**:
  - Partiful でも、招待ツールの収益化は遅く、手数料の公表も控えめ。主催者が無料のサービスは、収益源が店の売上からの手数料に限られる。
  - 誕生日会は **1 人あたりの客単価が低い**（居酒屋の宴会レベル）可能性が高く、手数料率が数%では 1 件あたりの粗利が小さい。決済手数料（Stripe は一般に約 3.6% 前後。要確認）を引くと残りは薄い。
  - 店への月額課金は、LINEレストランプラス（1 年目は実質 0 円）の存在で取りにくい。
- **対策**:
  1. **収益を複数持つ**: 貸切成立時の手数料（5〜10% 程度）、ケーキ・花・装飾などの**アドオン販売**（Partiful の Instacart と同様）、店側の追加課金（優先掲載など）。
  2. **1 件あたりの客単価を引き上げる設計**: コース・ドリンクのプラン、貸切料、デザートプレートを標準にする。
  3. 試算（§8）で、**1 店舗あたり月に何件の貸切が成立すれば粗利が出るか**を先に確定する。
  4. 誕生日会に限らず、**同じ仕組みで歓送迎会・女子会・同窓会に広げられる設計**にして、単価と頻度を上げる。

### U5. 店側の協力が得られない・運営負荷【可能性: 中 / 致命度: 高】

- **理由**: 貸切は仕込み・人員の確保が必要で、繁忙時は通常客の機会損失になる。誕生日会は **飾り付け・サプライズ・ケーキ持ち込み**などの個別対応が増え、店が嫌がる可能性がある。サプライズ対応を提供している店はすでに多い（ぐるなび・ホットペッパーの掲載）が、それは**店が自分のペースで受ける形**であり、主催者が自由に企画してくる形ではない。
- **対策**:
  1. 貸切可能な **曜日・時間帯・最低消費額・人数・受付期限・持ち込み可否**を店が細かく設定でき、店の承認制にする。
  2. 店の負担を減らす: 参加者の注文確定リスト、アレルギー情報、人数が確定した時点で仕入れ・仕込みができる。
  3. サプライズ・装飾は **店が定めたオプションメニューの範囲**に限定する。
  4. 初期は **すでに貸切・サプライズ対応を実施している店**から開始する。

### U6. 既存の代替手段で足りる（乗り換える理由が弱い）【可能性: 高 / 致命度: 中〜高】

- **理由**: 主催者は LINE グループで友達を集め、ぐるなびやホットペッパーで店を予約し、割り勘は PayPay などで行っている。**現状でも困っていない**可能性がある。Partiful がアプリ不要で成功しているのは、**出欠・連絡が面倒という課題**が大きかったから（一般知識）。日本では LINE がそれを解決している。
- **対策**:
  1. 「店の予約・事前決済・出欠・割り勘・アレルギー確認が **1 つのリンクで終わる**」体験を差別化の核にする。
  2. LINE と競合せず、**LINE グループへ招待リンクを貼るだけ**で使える設計にする。
  3. 解決する課題の優先順位を検証で確認する（日程調整、集金、店探し、サプライズ手配のどれが最も面倒か）。

### U7. 「出会いの場」を前面に出すことの法務・安全・ブランドリスク【可能性: 中 / 致命度: 高】

- **理由**（以下は一般論。**専門家確認が必須**）:
  - 異性との出会いを目的とした仲介を行う場合、**出会い系サイト規制法**（インターネット異性紹介事業）や、参加者から対価を取る場合の関連法令に抵触しないか確認が必要。
  - 友達の友達が参加する形でも、**ナンパ・ハラスメント・勧誘（マルチ商法・宗教・投資）**が持ち込まれるリスクがある。店のブランドにも傷がつく。
  - 結婚式二次会のノリで酒類を提供する場合、**未成年・泥酔・事故**のリスクがある。
  - 街コンなどの出会いイベントの先行事業者は存在する（今回は未調査）。
- **対策**:
  1. **「出会いの場」を主目的にしない**。「友達と祝う会」を主軸にし、出会いは副次的な結果として扱う。初期の訴求に出会いを使わない。
  2. 参加を **主催者の招待に限る（クローズド）**。参加者は主催者の友達または友達の友達まで。公開募集はしない。
  3. 本人確認（LINE ログイン＋電話番号認証）、通報・ブロック・店による参加拒否権、営利・勧誘の禁止規約を整備する。
  4. 出会いを訴求する場合は、**法務確認後**に段階的に追加する。

### U8. 需要が季節・日付に偏り、稼働が安定しない【可能性: 中 / 致命度: 中】

- **理由**: 誕生日会は金曜・土曜の夜に集中しやすい。店が貸切を出したくない繁忙時間に需要が偏る一方、平日の閑散帯には需要がない（推論）。
- **対策**: 平日・ランチ・休日昼の **貸切割引**を店に設定させる。時間帯別の最低消費額（繁忙時は高く、閑散時は低く）。**ランチ・アフタヌーンティー形式**の誕生日会を提案する。

### U9. 競合・代替の追随【可能性: 中 / 致命度: 中】

- **理由**: ぐるなび・ホットペッパー、Rounge、スペースマーケットが「招待・出欠」機能を足せば代替できる（技術的参入障壁は低い）。Partiful や Luma が日本に参入する可能性もある。
- **対策**: 機能ではなく **店舗ネットワーク（誕生日貸切に協力的な店の密度）**と、**既存会員データ・誕生日の導線**で優位を作る。特定の地域・業態に集中して先行する。

## 6. 先行した場合の収益構造（仮説）

| 収益源 | 内容 | 規模感 |
| :-- | :-- | :-- |
| 貸切成立の手数料 | 参加費の 5〜10%（店から徴収） | 1 件あたり数千円〜（客単価・人数に依存。要試算） |
| アドオン | ケーキ、花、装飾、プレゼント、カメラ撮影など（Partiful の Instacart 型） | 仲介手数料 |
| 店向け月額 | 優先掲載、会員向け配信、分析 | 低額（LINE の無償化に注意） |
| 広告・店舗プロモーション | 誕生日月の特集 | 将来 |

最も重要な指標は **「1 店舗あたりの月間貸切成立数 × 1 件あたりの粗利」**。これが店・shokujii の双方にとって意味のある水準になるかを §8 で確認する。

## 7. 一体型コミュニティ案との関係

| 項目 | 一体型（前回の案） | 誕生日会入口の案 |
| :-- | :-- | :-- |
| 入口 | 店のコミュニティ（常連） | 個人の誕生日（友達を呼ぶ） |
| 需要 | 不特定・日常的 | 年 1 回・日付確定 |
| 密度の課題 | 高い（過疎化） | 低い（友達を呼ぶので 1 件で完結） |
| 主催動機 | 弱い | 強い |
| 拡張 | 掲示板・サブスク | 歓送迎会・女子会・同窓会・推し活 |

**誕生日会は「会員主催貸切」の最小の需要検証単位として有効**。成功すれば、その参加者が店のコミュニティの種になる（チャット・サブスクは後から足せる）。

## 8. 検証計画（本開発の前）

| 検証 | 方法 | 判断基準（仮置き） |
| :-- | :-- | :-- |
| 主催の需要 | 協力店 5〜10 店で、既存会員の誕生日月に貸切を案内する（LINE・店頭）。申込フォームを手動で受付 | 4 週間の案内数に対する主催申込率、成立数 |
| 主催者像 | 申込者に「誰のために、なぜ主催したか」をヒアリング（本人／友人／推し／子ども） | 主な層を特定できる |
| 費用負担 | 割り勘／主役無料の割り勘／主催者全額の選択率 | 主役無料の割り勘の許容度 |
| 店の収益 | 貸切 1 件あたりの売上・粗利・追加の手間を店に確認 | 通常営業より利益が出る、または同等 |
| 手数料 | 手数料 5%・8%・10% への店の反応 | 一定の店が許容する |
| 友達からの循環 | 参加ゲストのうち、後日自分も主催したい／別の店で使いたいと答えた割合 | 一定の割合で次の主催が生まれる |
| 法務 | 出会い関連の規制、決済スキーム（店舗直接入金）、酒類提供、個人情報を専門家に確認 | 懸念がない／許容範囲 |
| 競合 | ぐるなび・ホットペッパー・Rounge・スペースマーケットの実機能を確認し、招待・出欠・割り勘の有無を確認 | 一体で提供するサービスがない |

## 9. 判断サマリ

| 区分 | 内容 |
| :-- | :-- |
| 成り立つ条件 | (1) 日本で主催者が現れる（友人主催・推し誕を含む）ことが検証で確認できる (2) 店の既存会員の誕生日データから能動的に案内できる (3) 主催者の負担ゼロ（不成立なら全額返金・主役無料の割り勘）を実現できる (4) 1 件あたりの粗利が店・shokujii の双方で成立する (5) 出会いの訴求を後回しにして法務リスクを避ける |
| 失敗に直結する要因 | 主催文化の弱さ（U1）、チラシ経由の低い転換（U2）、主催者の負担（U3）、収益性（U4） |
| 最初にやること | 協力店で、既存会員の誕生日月に貸切案内する**手動検証** |
| 推奨しない進め方 | 「出会いの場」を主訴求にする、チラシのみを集客の入口にする、本人主催だけを前提にする、アプリを先に作る |
